# Architecture of the analyzed app

> **Last reviewed:** 2026-11-16 · **Last updated:** 2026-11-16 · **Change:** minor (translated to English) · **Target:** local VSCodium 1.147.0 (VS Code `22d8dccf0f29`, Electron 43.8.6)

This is the overall picture:
- which processes the app opens;
- which bundle each one loads;
- which source-tree file that bundle starts from;
- where the data lives.

The contents of each bundle have not been studied yet (see [`lacunas.md`](lacunas.md) G1). The names and paths below were measured in the package and the source tree.

## 1. Processes

```text
                    codium (Electron main)  ── out/main.js → out/mainImpl.js
                     │
   ┌─────────────────┼──────────────────┬────────────────────┬───────────────────┐
   │                 │                  │                    │                   │
 workbench window  sessions window  shared process       pty host           agent host
 (renderer)        (renderer)       (utility)            (utility)          (utility)
 workbench.        sessions.        sharedProcessMain    ptyHostMain        agentHostMain
 desktop.main.js   desktop.main.js     │
   │                                   └─ file watcher (watcherMain)
   ├─ extension host (Node): extensionHostProcess.js
   ├─ web worker extension host: extensionHostWorkerMain.js
   └─ web workers: editor, TextMate, notebook, search, language detection, output links, images, profiling

 CLI: bin/codium → out/cli.js → vs/code/node/cliProcessMain.js (with ELECTRON_RUN_AS_NODE)
```

|---|---|---|---|
| Main | `main.js` → `mainImpl.js` | 0.1 MB · 1.3 MB | `src/main.ts`, `src/mainImpl.ts` |
| Workbench window | `vs/workbench/workbench.desktop.main.js` (+ `vs/code/electron-browser/workbench/workbench.js`) | 21.4 MB | `src/vs/workbench/workbench.desktop.main.ts` |

| Extension host | `vs/workbench/api/node/extensionHostProcess.js` | 2.2 MB | same |

The full list, with each one's entry, is in [`fonte-vs-pacote.md`](fonte-vs-pacote.md) §1. `nls.messages.js` (1.7 MB) has no entry: it is generated by the extraction of translatable strings (31,398 messages from 2,411 modules, measured in the build log).

## 2. Source-tree layers

They are the same as in VS Code ([`fonte/arvore/.github/copilot-instructions.md`](../02-engenharia-reversa/fonte/arvore/.github/copilot-instructions.md) describes the original pattern):

| Folder (`src/vs/`) | Role | May import |
|---|---|---|
| `base/` | cross-platform utilities and abstractions | nothing above it |
| `platform/` | services and dependency injection | `base` |
| `editor/` | the text editor (Monaco) | `base`, `platform` |
| `workbench/` | the full UI (parts, contributions, extension API) | the ones above |
| `sessions/` | the agent sessions window | the ones above, including `workbench` |
| `code/` | Electron entry points (main, shared process, CLI) | the ones above |
| `server/` | remote server (not packaged in this build) | the ones above |

Within each layer, the folder suffix says where the code runs:
- `common/`: anywhere;
- `browser/`: renderer;
- `node/`: Node;
- `electron-main/`, `electron-browser/`, `electron-utility/`, `worker/`: the matching Electron context.

## 3. Package on disk

```text
01-app/VSCode-linux-x64/
  codium                      Electron binary (with the VSCodium identity)
  bin/codium                  CLI script
  resources/app/
    out/                      32 JS bundles + media; no source maps in the main bundles (ADR 0001)
    node_modules.asar         191 runtime modules (list in 02-engenharia-reversa/asar/)
    node_modules.asar.unpacked/  native modules (.node) and files that must stay outside the asar
    node_modules/             semver, shell-quote, zod, @pondwader/socks5-server, @vscode/sandbox-runtime (outside the asar on purpose)
    extensions/               93 built-in extensions
    node-compile-cache/       V8 cache for main, extension-host, shared-process, pty-host, agent-host (UID 1000)
    product.json              VSCodium identity + keys added by packaging
```

The agent host only looks for modules in `node_modules.asar.unpacked` when the app has a recorded commit (`hasUnpackedNodeModulesArchive()` in `src/vs/platform/agentHost/node/appNodeModules.ts`); see [`aprendizado/0001`](aprendizado/0001-commit-muda-caminho-dos-modulos.md).

## 4. Data on disk

| What | Where (this build's default) | Origin |
|---|---|---|
| Settings and state | `~/.config/VSCodium/` | `nameShort` in `product.json` |
| Installed extensions | `~/.vscodium/extensions/` | `dataFolderName` (ADR 0002) |
| Shared recents and trust | `~/.vscodium-shared/` | `sharedDataFolderName` (ADR 0002) |
| System policies | `/etc/vscodium/policy.json` | read by the policy watcher (seen in the log with `--verbose`) |
